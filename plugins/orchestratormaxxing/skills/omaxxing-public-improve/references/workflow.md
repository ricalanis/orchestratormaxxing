# Coverage-driven contribution

## Establish evidence and scope

Verify distinct source and destination identities when a private source is supplied.
Resolve host paths on each host; never reuse a laptop's absolute path on a server.
Read contribution policy, license, current default branch, open PRs and recently merged
work. Fetch successfully before selecting or branching. Never import private Git ancestry,
run an exporter to mirror whole trees, or rewrite a manifest to authorize an export.
Resolve necessary additions against actual operator authorization and repository policy.

Freeze the inclusive start/exclusive end timestamps and record source refs, statuses,
host provenance, and public base. Inventory commits, changed components, learning records
and relevant unfinished work; deduplicate by SHA without losing host evidence. Never use
mtime as proof of completion. Keep raw history, findings, company information and private
paths in an ignored source-local evidence directory or outside both repositories.

## Review the whole landscape before choosing

Use ten starting domains: planning; delegation; execution/recovery; installation/host
discovery; verification/CI; security/publication; memory/context; browser/design;
autonomous improvement; shared-server/fleet services. Adapt this list to the project,
recording why a domain is added or not applicable. Map tracked public paths to domains
to detect omitted surfaces, then inspect actual interfaces and test boundaries. Do not
pretend a directory listing is a behavioral audit.

Maintain a coverage table with domain, evidence inspected, public gap, dependency closure,
host benefit, selected/already-present/deferred/excluded/unverified disposition, reason,
and required regression oracle. Map every discovered source item and commit to it.
Investigate reusable mechanisms before declaring a whole server/integration directory
private. Confidential data, credentials and tenant-specific configuration remain private.
New features are selected for demonstrated utility and maintainability, not file quotas.

For each selected capability, record the projection: source intent/evidence, public
before/after behavior, deliberately changed or omitted behavior, public paths,
dependencies, host contracts, functional checks and security checks. A capability is
incomplete if its entry point ships but its runner, schema, migration, configuration,
documentation or required test is missing. Distinguish a portable command/skill from
server API or dashboard support; do not imply parity without checking every layer.

## Plan, delegate, integrate

Persist a root-authored read-only brief and contract before `astraplan`. Root accepts
the design and owns architecture, installer changes, credentials and publication.
Use native `cheap-delegate` with current routing evidence and live model resolution.
Each writing worker gets its own worktree, bounded owned paths and acceptance contract.
Use `o delegate` for initial workspace work, `o send` only for repairs, `o handoff`
for typed output and `o close` on every terminal path. Response-only `oll` receives only
cleared supplied text. Record actual attempts and canonical receipts, including failure
and infrastructure outcomes. A worker's report cannot certify the gate.

Create fresh public commits from the fetched base. Prove meaningful new regressions red
on that base and green on the candidate. Re-run every affected contract on the final
combined tree after all workers finish. Preserve unrelated changes and explicit planner
alternatives; do not globally remap interactive models.

## Reconcile and publish

Before security review, reconcile discovered items, selected capabilities and changed
public surfaces with the final tree. Report separate counts: inventory items accounted
for, domains reviewed, selected contracts passed/required, and host modes measured.
Unverified rows remain visible. No claim of exhaustive branch coverage follows from
complete inventory accounting. Use the projection checker supplied by
`public-improve-security` to reject missing declared rows; root still validates evidence.

Run required local checks and isolated macOS/Linux contracts for affected host modes.
Tests must not call live models or production services. Verify optional-server absence
and relevant recovery paths with fixtures. A Linux container pass does not prove host
service-manager behavior or provider availability.

Complete the five security passes against all outgoing commits, full changed payload
and final PR title/body. Include capability projection fidelity and omission review.
Refresh public main before sign-off; a changed base/head invalidates prior security
receipts and requires renewed review. Allow one integration/retest cycle; continued
upstream movement is a checkpoint, not permission to publish an unverified tree.

The private final receipt binds repository, base/head, tree, outgoing commit IDs,
title/body hashes, projection contract/report hashes, five pass results and native
receipts. Immediately verify it before each public write. Reconcile existing branch/PR
state before retrying uncertain writes. Never force-push, merge or enable auto-merge.
Public PR text describes benefits, dependency/host limits, actual tests, security coverage
and explicit deferrals using public-safe evidence. Keep raw reports private. Confirm CI;
pending is not passing. Return the PR, truthful coverage, or a concrete blocker/no-work
result supported by the completed review.
