# Worker-path benchmark protocol

This benchmark compares worker harnesses while holding the task, model, timeout, and
acceptance check constant. It is an experiment, not a harness leaderboard: a result
is attributable only to the exact adapter/model/version recorded in the run.

## Required invocation

```text
bin/worker-path-bench \
  --cases experiments/worker-path-bench/cases.jsonl \
  --adapter NAME='COMMAND [ARG ...]' [--adapter ...] \
  --output results.jsonl --summary summary.json
```

Each adapter receives a sanitized case object on standard input. The runner strips
`answer`, `contract`, `expected`, and any `verifier_*` fields via `adapter_payload(case)` before
sending, so the expected answer and any verifier-only secrets never reach the adapter.
The adapter must emit one JSON object on standard output:

```json
{"output":"PONG","usage":{"prompt_tokens":1,"completion_tokens":1},"events":[]}
```

The runner must execute argv directly (never through a shell), enforce each case's
finite positive `timeout_seconds`, and emit one normalized result per adapter/case.
Adapter stderr is diagnostic metadata, never executable input. A malformed envelope,
timeout, signal, non-zero exit, missing/non-executable adapter, or combined stdout+stderr
output over the limit is an infrastructure failure rather than a contract failure.

Output from the adapter is capped to a combined stdout+stderr byte limit (default 1 MiB);
once exceeded, the runner terminates the complete process group and sets
`output_limit_exceeded: true`. `timeout_seconds` must be a finite positive number when supplied; an omitted value
defaults to 30 seconds. Invalid values are rejected before any adapter runs. The deadline
covers input delivery, output reads and process completion. Timeouts and cancellation
terminate the process group, including descendants retaining pipes after the leader exits.
Adapters are operator-selected local programs, not sandboxed untrusted code; a process
that deliberately detaches into a new session is outside process-group containment.

## Scoring

- `exact`: normalized `output` must equal `expected`.
- `json_fields`: `output` must parse as a JSON object containing every expected
  key/value pair; extra fields are permitted.
- Summary metrics per adapter: total, passed, contract failures, infrastructure
  failures, schema-valid envelopes, latency p50/p95, plus long-context diagnostics:
  proxy input tokens, actual prompt tokens when present, compaction count derived
  from envelope `events`, cache-read tokens from events, and protected-fact losses.
  Unknown measurements are null; summaries include observed-case counts alongside
  partial totals. An explicit empty event list measures zero compactions, while an
  omitted event list is unknown. Usage values must be finite nonnegative numbers;
  malformed usage/event metrics are infrastructure failures.
- Raw normalized JSONL remains the source of truth. The summary must be reproducible
  from it and must not hide failed or timed-out cases.

## Long-context canaries

Long-context cases are opt-in and generated by `generate_context_cases.py --sizes`
emitting `size × {instruction, retrieval, code_state} × {beginning, middle, end}`.
Each case embeds a protected fact at a controlled needle position and uses an `exact`
contract; `protected_fact: true` marks it for the loss/retrieval metrics above.

Stages run at 16k, 32k, 50k, 64k, 96k, 128k, and 192k target input tokens. A model
or adapter promotes to the next stage only after passing at least 8 of 10 trials at
the current stage, treating any protected-fact miss as a stage failure. These cases
are intentionally separate from the main pass@1 gate; the protocol does not adopt a
production compaction threshold.

## Case input

Each JSONL row needs a unique nonempty string `id` and a `contract` containing a
supported `type` and `expected`. `json_fields` requires a nonempty expected object.
A `prompt` is conventional adapter input; other explicitly supplied case fields travel
unless excluded above. Do not put credentials or undeclared verifier data in cases.
Optional `target_input_tokens` and `estimated_input_tokens` are nonnegative integers,
not measured usage. No live provider is called by the supplied synthetic fixtures.

The CLI and scorer require Python 3 and POSIX process groups (macOS/Linux). The installer
places the scorer beside its toolkit data under the user's local share directory.
Results contain expected answers and adapter outputs: choose an appropriate private
output location for real experiments. This protocol describes measurement mechanics;
synthetic fixture results do not establish any model's quality.
