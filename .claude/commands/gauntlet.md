You are the **orchestrator** of a Gauntlet Loop. The request: **$ARGUMENTS**

**Position (load-bearing):** this runs **one step BEFORE planning** — it divides a broad request into increments; it does NOT plan implementation (`/astraplan` keeps that job per part) and does NOT change execution routing. Invariant: **the gauntlet verdict promotes, never accepts** — deterministic contracts stay the only acceptance gate. Protocol + research: `knowledge/gauntlet-loop-design.md`.

0. **Fire or skip.** Fire when the request is broad or multi-deliverable enough that dividing it into increments helps. A single-deliverable or trivial request skips straight to the normal flow — say so in one line.
1. **Divide in a sub-agent — not inline.** Spawn one `ollama-worker` (Task tool) on `deepseek-v4-pro` to propose 3–7 **incremental** parts: each independently shippable and verifiable on its own, ordered so every increment lands value without the later ones. Per part: artifact spec, candidate real-world reference R + provenance (model family / `human` / `unknown`), and 5–8 candidate boolean rubric criteria. Fallback: `oll "<divide brief>" --model deepseek-v4-pro`.
2. **Ratify the division (Tier-0).** The decomposer *proposes*; you *author*: fix the order, per part fix the rubric (mark load-bearing criteria, write it to a scratchpad JSON `[{"id","text","load_bearing"}]`) and author the deterministic acceptance contract. Check `win-log match --class <class>`. A part whose contract or rubric you can't state is underspecified — refine or merge it. No scope-matched R (same artifact type, same requirement, comparable granularity)? The part still gets rubric + critic mandate; it's just "ungated-vs-baseline" at delivery.
3. **Hand each part to the normal pipeline, unchanged.** Nontrivial part → `/astraplan` designs it, then build per the approved plan. A small response-only artifact may use `oll`; code that reads/edits the workspace uses `/cheap-delegate` or `o delegate <run-id> --profile bounded-code|reasoning|long-horizon|general --run-dir .results/delegation/<run-id> --json`, with `o close <session>` on every terminal path. Work increments in order; each lands before the next starts.
4. **Accept each increment deterministically.** Contract (Tier 1a); `bin/mut` for risky parts (1b). **One shared repair budget of 2 rounds per part** across contract failures and gauntlet refutations; early-exit if the failure diff isn't shrinking.
5. **Gate each increment's delivery (promotion).** Where R exists:
   `gauntlet-judge --artifact <G> --reference <R> --rubric <rubric.json> --builder <model> --reference-author <family|human|unknown> --json`
   Read only the JSON. Exit 0 = promoted; 1 = not-shown-better (fail-closed); 3 = gate unavailable — report it, never retry until it passes. On exit 1: each entry in `refutations_of_artifact` is a *claim* (critics hallucinate, arXiv:2407.00215) — adjudicate deterministically; if real, add one targeted assertion to the contract and spend a repair round (step 4's budget). **Never re-roll judges seeking a pass** (Goodhart, arXiv:2210.10760). First use of a judge pair per task class, or a surprising verdict → `--canary` first (R-vs-R must tie, null must lose 4/4); canary fail = the panel's verdicts are unusable, parts report "ungated-vs-baseline". Where no R exists: a **Tier-2 cross-family critic** (different family than the builder, framed external: "another agent produced this — try to refute it") — never the panel reference-free (arXiv:2210.12563).
6. **Report + record.** Per increment: contract result, mut score (if run), delivery verdict + flags (`length_flag`, `reference_provenance_unknown`), R provenance, repair rounds used. `win-log add --class <class> --shape gauntlet-N --workers <builders+judges> --survivors <real 1b count> --delivered` **only when 1b actually ran clean**.

Spend Opus only on ratification, adjudication, and merge; the sub-agent divides, builders build, the tool judges, contracts accept.
