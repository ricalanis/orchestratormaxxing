# Contributing to orchestratormaxxing

Main is regenerated by graduation. PRs are welcome; a merged change is absorbed into the private source of truth and re-graduated, so your PR will be closed with a comment naming the commit that carries it (that is success, not rejection).

## How a change must arrive

- Keep it to graduated paths (see the manifest in `deploy/graduation.manifest`).
- Run `bin/harness-verify` locally (fresh `HOME` if you like).
- Add or extend a contract under `tests/<name>/run.sh` for behaviour changes.
- Prove a new assertion red first.

## `tests/` conventions

- **Hermetic** — tests run in a controlled environment.
- **Real-boundary** where the tool's job is a boundary — exercise the actual interface.
- **Deterministic exit codes** — 0 pass, 1 fail, 77 skip.
- **No network** — tests must not reach out.
- **SKIP protocol** (exit 77) for missing host tools.

## What will be refused

- Anything touching non-graduated paths.
- Secrets, PII, or business data.
- Weakening a `block` rule.
- Session-wide model remaps (see CLAUDE.md § fableplan rollback).

## Commit/PR etiquette

- One concern per PR.
- Conventional prefixes: `feat`, `fix`, `docs`, `chore`.
- No force-push to main (it is tool-owned).
