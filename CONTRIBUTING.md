# Contributing to orchestratormaxxing

Contribute fresh commits based on current public main through a focused pull request.
A private source repository, personal infrastructure and graduation manifest are not
required. Preserve independent public work and describe the concrete behavior improved.

## Prepare a contribution

Use `omaxxing-public-improve` for scope, dependency closure and implementation, and
`public-improve-security` for the five-pass review before publishing a branch or PR.
`weekly-public-contribution` adds recurring discovery, backlog review and checkpoints.
New public paths are welcome when their interfaces, installation, documentation and
necessary tests travel together. Never copy private Git history or whole source trees.

Keep private evidence, client/employer material, credentials and raw logs out of payloads,
commit messages and PR metadata. Verify ownership, upstream attribution and redistribution
rights. Use independently invented fixtures. Optional hosts/services must remain optional.

## Verification

Run `bin/harness-verify` and all affected contracts on the final combined tree. New
executable behavior needs meaningful negative controls or a regression shown red before
its fix. The required weekly contribution suites run separately in the macOS/Linux CI
matrix so a skipped or inconclusive general check cannot certify the new capability.

Contracts run offline in isolated homes/workspaces and must not invoke live agents or
production services. Exercise real process/filesystem boundaries where relevant. Exit
codes are 0 pass, 1 fail and 77 unavailable; unavailable required coverage blocks release.
Report simulated layouts separately from actual operating-system and host-runtime tests.
Instruction-level skill reviews complement, and do not replace, executable checks.

## Publication

One coherent concern per PR may include several dependent capabilities. Use conventional
commit prefixes, an evidence-backed before/after description, actual test results and
clear host/dependency limitations. Root owns final artifact review. Never force-push,
merge automatically or push the default branch from an agent contribution workflow.

## Legacy export compatibility

This project originated as a gated projection. The historical `graduate` and `core-export`
tools remain for explicitly configured operators, but they can replace destination files.
They are not the public contribution path. Their private schedules/configuration are not
changed by this repository update; operators must reconcile independent public additions
before running them. Do not treat an old EXPORT-MANIFEST.json as current public coverage.
