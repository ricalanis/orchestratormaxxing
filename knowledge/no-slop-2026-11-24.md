# No AI Slop: what this harness adopted and what it measured — 2026-11-24

Source: Dex Horthy, "12 Rules for a Software Factory That Doesn't Ship Slop" (AIE Code Summit 2026)
and the No AI Slop manifesto (gist dexhorthy/4cc96f01be5b1208519e75dad250a948).

## What ships here

| Piece | Where | Token cost |
|---|---|---|
| `no-slop` skill (the manifesto as agent actions) | `skills/no-slop` | one description line until loaded |
| `bin/slop-check` + vendored SlopCodeBench rules | `deploy/slop-rules`, installed by `install.sh` | zero model tokens; measurement only |

`slop-check` scans the Python lines you changed (since HEAD, plus new files) with a hash-locked
ast-grep. Exit 0 clean, 1 findings, 2 cannot scan. It never edits code. It is a lint for repositories
you trust, not a security boundary; its limits are listed in `deploy/slop-rules/README.md`.

## What was measured

One run, one model: DeepSeek v4.1 Flash, temperature 0, on 8 SlopCodeBench problems (scb-problems),
checkpoints 1 to 3 each, 2 replicates, so 48 cells per arm. Each checkpoint got only the new spec and
the previous program. Every arm is the same short coding-rules system prompt plus one change. The
adoption rule was written down before the first scored call. Slop is scb-check ast-grep findings per
100 lines over all 197 rules. Pass is the share of the current checkpoint's tests passed. The
problems' reference solutions pass 100% in the same runner.

| Arm | Pass | Strict passes | Slop/100 | Verbosity | Tokens | Verdict |
|---|---|---|---|---|---|---|
| base prompt (control) | 61.0% | 4 | 7.57 | 0.132 | 496k | — |
| + SlopCodeBench's anti-slop prompt list (82 words) | 63.8% | 5 | 7.82 | 0.071 | 483k | not adopted: slop flat (22 cells lower, 22 higher) |
| + "you own this codebase" (22 words) | 58.1% | 4 | 8.81 | 0.146 | 553k | not adopted: more slop in 26 of 38 differing cells, p = 0.034 |
| + prose digest of 25 frequent rules (395 words) | 61.2% | 5 | 6.92 | 0.095 | 511k | not adopted: −7% on paired cells, p = 0.88 |
| + lint gate (findings fed back once) | 58.4% | 4 | 7.77 | 0.137 | 875k | not adopted: the fix pass removed 14% of the findings it was shown (671 to 578) for +76% tokens; final slop not below control |
| + two sentences condensed from the manifesto (35 words) | +10.6 pts vs control | +2 / −0 | −9% | −25% | — | passed a no-regression rule |

The two sentences, in this harness's own wording: "Own what you ship: never hand over output that costs the reader more effort to
understand than it cost you to make. Prefer removing to adding, and fix the cause instead of working
around it."

## Reading the result

- Telling a cheap worker it owns the codebase made its code measurably worse. Do not add that line
  to worker prompts on the strength of the claim alone.
- The benchmark's own anti-slop prompt halved verbosity (duplicated and flagged lines) and cost fewer
  tokens, but missed the primary measure chosen in advance. Worth a second run with verbosity as the
  primary measure.
- One fix pass of lint feedback did not pay with this model: the control arm ended with the same
  number of findings on the gated rules (578) without any fix pass. Not tested: frontier models, or a
  gate that reports only new findings.
- Limits: one run, one model, Python only, 48 cells per arm. Treat the numbers as a first reading.
